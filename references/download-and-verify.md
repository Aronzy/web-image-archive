# 下载、清单与恢复

## 清单

每批维护 UTF-8 JSON 清单。字段建议：

```json
{
  "source_page": "作品或白板页面",
  "source_id": "站点稳定的原始资源标识",
  "file": "image-001.jpg",
  "quality": "original",
  "quality_evidence": "与作品元数据的 original 版本对应",
  "expected_width": 1920,
  "expected_height": 1080,
  "expected_bytes": 262749,
  "actual_width": 1920,
  "actual_height": 1080,
  "actual_bytes": 262749,
  "sha256": "下载后计算",
  "source_checksum_algorithm": "md5",
  "source_checksum": "仅在来源确认算法时填写",
  "status": "verified"
}
```

未知信息使用 null 或省略，不能补造。资源 ID 应结合站点/白板命名空间去重；不要将不同站点同名 ID 混为一个。临时签名 URL 单独保管，长期清单保留 canonical 来源页即可。

## 下载事务

1. 从历史清单和可选目标库建立稳定 ID 与 SHA256 集合。用户删除或移动文件后，记录“已处理但文件缺失”，不默认重抓；按当前任务判断是否需要修复。
2. 每张下载到本批独立 `.part` 文件，设超时与有限重试。失败即停的用户指令优先于自动重试。重试 GET 可以恢复下载；Eagle 写入不可据超时直接重发。
3. 验证 HTTP 状态和文件签名，拒绝 HTML 登录页、错误 JSON、空文件及截断数据。扩展名来自文件格式，不仅依赖 URL/Content-Type。
4. 用可用的图片解码工具确认文件可打开并读取尺寸。文件头解析可用于尺寸核验，但不能称为完成了整图解码验证。缺少解码器时使用宿主图片查看工具；新增依赖须遵守用户磁盘要求。
5. 比对可用的原始尺寸、字节数、确认算法的校验和。ETag 或任意资源 hash 不默认当 MD5。仅宽度高于 120 像素不是原图判据。
6. 计算 SHA256，排除本批及历史重复内容，记录重复来源。校验通过后原子改名并及时更新清单；输出文件存在时先验证，绝不直接覆盖。
7. 分组完成后核验准确张数、来源对应、组间去重。若唯一图片不足，报告不足数量，不用重复项凑数。

采用少量并发或顺序下载，遇限流减少频率。不要用时间戳变化掩盖重复导出。暂停后从已验证清单恢复，不从零开始。

## 交付

报告每批数量、质量等级、目录和未完成项。对原图主张说明验证依据。保留下载清单、质量验证结果，以及可选 Eagle 导入回执；不得用“请求已提交”代替“文件已验证”。
